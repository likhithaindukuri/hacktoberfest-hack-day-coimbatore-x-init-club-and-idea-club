## Problem Statement

### The Problem

[When an unexpected incident occurs in a laboratory, workspace, or other environment, understanding what happened often requires examining incomplete visual evidence and considering multiple possible explanations.

A single incident image may contain useful clues such as objects, their positions, visible damage, stains, or unusual conditions. However, identifying what is visible and determining what may have happened are two different tasks.

Traditional image analysis systems can identify objects or describe a scene, but they do not necessarily provide a structured reasoning process for comparing multiple possible explanations.]

### Why We Chose This Problem

[We wanted to build an AI system that goes beyond simple image captioning.

The goal is to separate:

What can be observed from what might have happened.

This makes the system more transparent and allows the final explanation to be based on visible evidence rather than an unsupported conclusion.]

## Solution

[We developed AI "What Went Wrong?" — Incident Detective, a multimodal AI system that takes:

An incident scene image
A short description or context provided by the user

The system first sends these inputs to Gemma 4, which analyzes the scene and produces structured information including visible objects, conditions, evidence, possible explanations, and uncertainties.

The generated evidence and possible explanations are then passed to Laya, which evaluates the candidate explanations and assigns confidence scores based on the evidence.

The final dashboard presents the explanations and highlights the explanation with the highest confidence.

The system therefore follows:

Gemma sees → Evidence is extracted → Laya evaluates → Explanations are ranked

The system is designed as an incident hypothesis and reasoning assistant, rather than a forensic or safety authority. Its explanations represent possibilities based on available evidence and should not be treated as definitive conclusions.]

### Key Features

Upload an incident image for multimodal analysis.
Provide additional incident context through text.
Use Gemma 4 to identify visible objects, conditions, and evidence.
Generate multiple plausible explanations dynamically from the scene.
Explicitly identify uncertainties in the available evidence.
Pass Gemma's structured output to Laya for independent evaluation.
Generate confidence scores for candidate explanations.
Display all candidate explanations and their supporting evidence.
Highlight the highest-confidence explanation on the dashboard.
Maintain a clear separation between visual evidence and inferred explanations.

## Innovation and Differentiation

[The main idea behind the project is the separation of scene understanding and decision-making.

Instead of asking one AI model to directly determine what happened, our system uses two complementary stages.

Gemma 4 — Perception and Hypothesis Generation

Gemma 4 analyzes the image and context to determine:

What is visible
What conditions are present
What evidence can be extracted
What explanations are plausible
What information remains uncertain
Laya — Evidence-Based Evaluation

Laya receives the structured output generated by Gemma and evaluates the possible explanations against the available evidence.

This creates an interpretable pipeline where the user can see:

Evidence → Possible Explanations → Confidence Scores

Rather than hiding the reasoning process behind a single prediction.]

### How It Works

[1. Incident Input

The user uploads an incident image and enters a short description or context.

For example:

Image:
A photograph of a messy laboratory workspace

Context:
This incident happened in an electronics laboratory.
2. Gemma 4 Analysis

The image and context are provided to Gemma 4.

Gemma performs multimodal analysis and returns structured JSON containing:

{
  "visible_objects": [],
  "visible_conditions": [],
  "evidence": [],
  "possible_explanations": [],
  "uncertainties": []
}

The arrays are dynamic. Their number of elements depends on the content of the image and the information that can be reasonably supported.

3. Evidence Display

The dashboard displays the information generated by Gemma.

This includes:

Visible objects
Visible conditions
Evidence
Possible explanations
Uncertainties

All relevant evidence returned by Gemma is displayed rather than restricting the output to a fixed number of items.

4. Laya Evaluation

The user can then request an evaluation using Laya.

The structured Gemma output is passed to Laya.

Laya evaluates the candidate explanations using the evidence and generates a confidence score for each explanation.

5. Final Result

The explanations are displayed as cards in the dashboard.

The highest-confidence explanation is highlighted as:

Most Likely Explanation

Alternative explanations remain visible along with their confidence scores and supporting evidence.]

### Technical Decisions

[Structured JSON Between Components

Gemma does not directly communicate free-form text to Laya.

Instead, Gemma produces structured JSON containing evidence, hypotheses, and uncertainties.

This gives us a clear interface between the two AI components and makes the system easier to integrate with the frontend and backend.

Dynamic Evidence

The number of objects, evidence items, uncertainties, and explanations is not fixed.

Different incident scenes can contain different amounts of information, so the system dynamically handles the generated arrays.

Separate Perception and Decision Stages

Gemma is responsible for understanding the visual scene and generating plausible hypotheses.

Laya is responsible for evaluating those hypotheses based on the evidence.

This separation makes the system more explainable and modular.

Uncertainty Preservation

The system explicitly preserves information that cannot be determined from the image.

For example, an image may show a liquid spill, but it may not reveal:

What the liquid is
Who caused the spill
When the spill occurred
Whether a particular object caused the spill

These uncertainties are passed along instead of being treated as known facts.]
